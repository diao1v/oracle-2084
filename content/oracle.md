# What is this

This is ORACLE 2084, a records terminal about the subject, Yiwei Diao. You are talking to a retrieval-augmented generation system: your question is embedded, matched against a corpus of records about the subject in a vector index, and the matching fragments are handed to a language model that answers only from them. The fragments it used are listed beside each answer. If nothing in the records covers a question, it says NO RECORD rather than guessing.

It was built by the subject as a working demonstration of AI engineering. The whole system runs on Cloudflare: a single Worker serves this terminal and its API, Vectorize holds the embeddings, Workers AI runs the bge-m3 embedding model and the Llama 3.3 70B language model through AI Gateway with Guardrails, and Turnstile plus rate limiting keep bots out. The 3D Macintosh around this screen is the subject's portfolio site; pressing 2084 on it switches the machine from its 1984 daylight scene to this neon terminal.

## MCP server (Model Context Protocol)

MCP stands for Model Context Protocol, the open standard that lets AI assistants such as Claude, ChatGPT and Cursor call tools and read data from an external service. The subject designed and shipped PageProof's remote MCP server, a production MCP server that lets PageProof customers connect their AI assistant to their own PageProof data. He secured it with OAuth 2.1 and PKCE against the company's OIDC server, with JWT access tokens verified against JWKS and impersonation through the internal authorization service so the server never holds a system key. He wrote the tool contract, which the team then extended to 10 MCP tools, and hardened the server for production on Kubernetes on Azure behind a Cloudflare tunnel. This terminal, ORACLE 2084, is a different system; the MCP server is part of his work at PageProof.

## RAG systems (retrieval-augmented generation)

RAG stands for retrieval-augmented generation: a question is embedded, matching documents are retrieved from a vector index, and a language model answers from those documents only. The subject has built three RAG systems. At PageProof he built a Confluence RAG assistant on the Azure AI stack: Azure AI Search with integrated vectorization and hybrid retrieval, one Azure AI Foundry agent per team, and Azure Document Intelligence for screenshots, delivered as Slack bots that multiple teams use, each limited to its own Confluence spaces by a filter the search service enforces. Earlier, at Spark, he built a codebase RAG assistant with LangChain, Chroma and a local Ollama model behind a Next.js chat UI. And this terminal, ORACLE 2084, is a RAG system he built on Cloudflare: bge-m3 embeddings in Vectorize, Llama 3.3 on Workers AI, Guardrails through AI Gateway.
